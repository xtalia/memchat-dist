# Memchat Chrome 8.9.0.5

## Результат

- Оповещатель включается галочкой и сразу проверяет выбранные организации/статусы; дальнейшие циклы выполняет единый worker через Chrome alarms.
- Выключение останавливает alarm. Одновременные запросы вкладок делят один опрос; закрытие вкладки не отменяет фоновую службу.
- Проверка товаров удалена из Chrome-пакета и из настроек. Вместо неё — «Проверка запросов» с безопасными GET-пресетами, своим API-путём, HTTP-статусом, временем, количеством строк и JSON. Есть отдельная диагностика оповещателя и явно помеченное тестовое уведомление.

## Найденные проблемы

1. `hackerNotifierStart` на extension-пути только сохранял конфигурацию; немедленного запроса после включения не было. Теперь первый опрос следует после успешного подтверждения конфигурации, без отдельного таймера вкладки и без deadlock на собственной цепочке настройки.
2. Worker скачивал все заказы организации, затем фильтровал статусы локально. Read-only сравнение реального API показало 12 695 строк против 9 для одного выбранного статуса. Новый `filter` включает организацию и выбранные статусы; пагинация результата и отсутствие искусственных caps сохранены.
3. Частичный результат называл организацию, скрывая причину. Теперь виден фактический HTTP-код/текст ошибки; диагностическая вкладка не требует открытой панели «Новые заказы».

Для первых двух случаев и потери HTTP-причины зафиксированы RED → GREEN regressions. Проверка UI, запрета чужих хостов/секретов, маскирования JSON и удаления старой панели настроек также покрыта тестами.

## Проверка настоящего API

`extension/notifier-live-smoke.cjs` запускается только с явным `MEMCHAT_LIVE_READ_ONLY=1`:

- Отдельный принадлежащий тесту headless Chromium и упакованное расширение; рабочий браузер пользователя не меняется.
- Существующий credential source активного Hermes-профиля используется в памяти. В тестовом приватном хранилище расширения — только нерабочий placeholder. Проверено отсутствие настоящего ключа в local/session extension storage; профиль закрывается и удаляется.
- Только GET к реальному API; ответы не подменяются фикстурами. Изолированная HTML-страница заменяет сайт, но не HTTP-ответы МойСклад. Panel и звук колонок не считаются проверенными.
- Галочка «включено» без ручного PollNow → HTTP 200 с серверным фильтром → уведомление существующего заказа. На контрольном прогоне — 9 совпадений.
- Вторая вкладка не сдвигает alarm; после закрытия первой получает уведомления и диагностический результат.
- Обычный GET показывает HTTP 200 и одну строку. Ошибочный тип сущности возвращает настоящий HTTP 412 / API 1005, который отображается как ошибка.
- Выключение удаляет alarm; диагностика не включает оповещатель сама. Запросов позиций/внутренних заказов нет, бизнес-записей нет.

Отдельные synthetic browser smoke проверяют общий опрос двух вкладок, пагинацию, один показ результата, настоящий Chrome alarm без открытых страниц, приватное хранилище, транспорт и обновление загруженной unpacked-установки. Это отдельные доказательства, а не подмена настоящего API.

## Границы

Generated userscript, исходные core/DEV и незавершённая рабочая копия пользователя не изменяются. Разрешения Chrome, семь файлов расширения и формат V2 updater прежние. Нет локальных очередей, pacing, concurrency caps и квот. Временное чтение повторяется один раз; записи не повторяются автоматически.

Уведомления — внутри живой поддерживаемой вкладки, не системные push. После полного перезапуска браузера необходимо открыть Memchat для повторной настройки фоновой сессии. Автовоспроизведение звука зависит от разрешений Chrome. После обновления нажать стрелку перезагрузки на карточке расширения, затем обновить рабочие вкладки.
