# Хатико · Memchat для Chrome

Автономное расширение Chrome **Manifest V3**, версия `8.8.0.2` (`8.8.0-beta-chrome.2`). Содержит неизменённый production `memchat.user.js` версии `8.8.0-beta` и локальные extension-only адаптеры: фоновый CSRF Panel и верхний слой окон. Те же вкладки, калькуляторы, поиск Hatiko/Panel, расписание и функции МойСклад. Tampermonkey не нужен.

## Установка

1. Скачать [memchat-chrome.zip](https://github.com/xtalia/memchat-dist/raw/refs/heads/main/memchat-chrome.zip) и распаковать в постоянную папку.
2. **Отключить Memchat в Tampermonkey**, включая DEV-версию. Расширение и userscript нельзя запускать одновременно: иначе возможны дублирующие обработчики и уведомления.
3. Открыть `chrome://extensions`, включить **Режим разработчика**.
4. Нажать **Загрузить распакованное расширение**, выбрать внутреннюю папку `chrome-extension` с `manifest.json`, не ZIP и не родительскую папку.
5. Перезагрузить рабочие вкладки МойСклад, Bitrix24 или Hatiko.
6. Закрепить расширение в панели Chrome. **ЛКМ по значку** создаёт/показывает основное окно; повторный клик скрывает его. Popup-меню отсутствует.
7. **ПКМ по значку → Сбросить положение окон** возвращает основное и открытые плавающие окна в исходное положение, удаляет сохранённую позицию. История, введённый текст и настройки не очищаются.

Переключение видимости касается только основного окна: окна настроек и прочие плавающие окна не закрываются. Пункт отладки убран из управления расширением; общий код userscript не изменён. На неподдерживаемой странице или при необходимости перезагрузки значок показывает `!`; подсказка при наведении объясняет причину.

Chrome 120+; на Chromium 151 пакет проверен в headless-режиме. Установка в основном профиле пользователя не выполнялась.

## Обновление

Скачать новый ZIP, заменить содержимое **той же постоянной папки**, на `chrome://extensions` нажать **Обновить/Перезагрузить** для расширения, затем перезагрузить рабочие вкладки. Без Chrome Web Store или enterprise update-server автоматических обновлений нет. Публикация в Web Store не входит в этот релиз.

## Авторизация и данные

- Для Panel войти в `https://panel.hatiko.ru/` в **том же профиле Chrome**. Расширение использует существующую сессию браузера; пароли не входят в пакет.
- CSRF получается по необходимости фоновым HTML-запросом `/search` из service worker: вкладку Panel держать открытой и копировать токен вручную не нужно. Одновременные обращения делят один запрос и кеш в памяти worker до 12 минут; после его остановки токен запрашивается заново. Ошибка 401/403/419 запускает принудительное обновление и не более одного повтора API-запроса.
- CSRF не записывается в localStorage страницы. Старый `memchat:panelCsrf_v1` удаляется для текущего сайта; прочие настройки и история не затрагиваются. При истёкшем входе расширение сообщает об ошибке, но само не открывает окна/вкладки. Пароли, CAPTCHA и 2FA не обходятся; блокировка third-party cookies или политика браузера может помешать передаче сессии.
- Bearer API МойСклад включается в существующих настройках Мемчата. Ключ не вшит в расширение.
- Сохраняются исходные `memchat:*` localStorage keys. Поэтому настройки и история production-userscript в том же сайте/профиле продолжают работать; DEV-состояние не переносится.
- Настройки/история по-прежнему раздельны для разных сайтов/профилей. Исключение — CSRF Panel: один кеш в памяти worker на профиль расширения. localStorage принадлежит странице и доступен её скриптам: это прежняя модель userscript, **не защищённое хранилище секретов**. Bearer МойСклад остаётся в прежней модели; его перенос требует отдельной миграции.
- Телефоны вкладки «Бонусы» по-прежнему исключены из сохраняемой истории.
- Пакет не содержит паролей, Bearer-ключей, пользовательских данных или телеметрии. Все исполняемые скрипты локальны; сетевые ответы — данные/HTML/JSON, не remote code.

## Разрешения

- Site access: `online.moysklad.ru`, `*.bitrix24.ru`, `*.hatiko.ru` — только исходные `@match` сайта для content script и управления текущей рабочей вкладкой.
- Network access: исходные `@connect` (`hatiko.ru` и поддомены, Panel, `docs.google.com`, GitHub/raw, `api.moysklad.ru`).
- `activeTab` — действие по текущей рабочей вкладке; broad `tabs` не запрашивается.
- `contextMenus` — единственный собственный пункт «Сбросить положение окон» в ПКМ-меню значка расширения, не в меню страницы.
- `declarativeNetRequestWithHostAccess` — выставление фиксированных Origin/Referer для **собственных** запросов расширения к Panel; отдельное правило блокирует внешние redirect destinations. Обычные запросы страниц не переписываются.
- Нет `<all_urls>`, `cookies`, `webRequest`, `scripting`, clipboard permission или externally_connectable.

## Архитектура

- `content.js`: isolated-world IIFE, GM-адаптер, неизменённый production userscript и локальные `runtime.js` / `top-layer.js` адаптеры. Нет page postMessage bridge.
- `worker.js`: проверенный по sender/domain/method GM transport и отдельная команда фонового CSRF с фиксированным адресом. Cookie-сессии передаются через `credentials: include`; `anonymous` использует `omit`. Bearer разрешён только для `api.moysklad.ru`. CSRF кешируется только в памяти и не выводится в логи.
- `config.js`: allowlists из metadata userscript.
- `controls.js`: Chrome action/context-menu обработчики; управление через private runtime channel без popup, eval и page postMessage bridge. GM-menu регистрации userscript не экспортируются.
- `build-info.json`: версия и SHA-256 точного production input.

Таймаут отдельного запроса ограничен 30 секундами с учётом lifecycle MV3. Табличные/фоновые функции core продолжают жить в открытой вкладке, а не в постоянно работающем worker. Закрытие/заморозка рабочей вкладки останавливает их, как и у userscript; это не сервер мониторинга.

## Сборка и проверки

Исходники расширения: `hatiko/js/memchat/extension/`. Generated userscript вручную не редактировать.

Из `E:/gitreps/hatiko/js/memchat`:

```sh
# После обычной production-сборки memchat.user.js:
python extension/build.py
node --test tests/chrome-extension-*.test.js
node extension/smoke.cjs
npm test
```

`build.py` не пересобирает и не меняет userscript: получает уже собранный production input. Это позволяет не включать незавершённые src-изменения в extension release. Артефакты: `extension/dist/chrome-extension/` и `extension/dist/memchat-chrome.zip`. ZIP детерминированный; зависимости для Python-сборки не нужны. Четвёртый компонент Chrome version — revision адаптера, независимый от версии core. При пересборке удаляются известные retired popup-файлы; при ручном обновлении установленной папки тоже удалите `popup.html`, `popup.js`, `popup.css`, если они остались от первой версии.

Smoke использует уже установленный Playwright и отдельный временный headless Chromium профиль. Пути можно задать переменными `MEMCHAT_PLAYWRIGHT` и `MEMCHAT_CHROMIUM`. Он проверяет действительную загрузку пакета, native-menu регистрацию, переключение видимости, сброс позиций, сохранение текста/истории/настроек, калькулятор, runtime HTTP channel, публичный GitHub redirect и live `hatiko.ru`. В headless нет видимого toolbar: вызываются те же функции, которые зарегистрированы в Chrome action/context-menu событиях, с настоящими tabs/runtime APIs и content scripts. Пользовательский профиль и бизнес-документы не меняются.

## Окна поверх страницы

Основное окно, плавающие настройки и диалоги Мемчата используют **top layer браузера** через немодальный `popover="manual"`: обычный `z-index` сайта их не перекрывает. Внешние клики проходят к странице, если не попали в окно; черновик, история, размеры и кнопка скрытия сохраняются. При открытии новых popover/dialog страницы слой поднимается заново; внутри модального диалога host размещается в его поддереве, чтобы окно не стало `inert`.

Это верхний слой **текущей вкладки**, не режим «поверх всех приложений» Windows и не размещение над интерфейсом самого Chrome. На браузере без Popover API остаётся исходное поведение; Chrome 120+ поддерживает используемый API.

## Границы проверки

- Production input взят из чистого release-worktree без незавершённых src-правок. Его текст совпадает с опубликованным `memchat-dist/main/memchat.user.js` после нормализации CRLF/LF; точные входные байты и их SHA-256 зафиксированы в `build-info.json`. Оба опубликованных userscript-файла в этом extension-only релизе не изменяются.
- Чистый release-worktree базируется на актуальном `origin/main`; незавершённая отладка/настройки внутренних заказов в основном checkout не включены. До изменений все 67 тестов чистого baseline проходили; после изменений полный suite: **92 passed, 0 failed**. Packaged smoke в Chromium 151 также прошёл: начальный фокус, новые/вложенные модальные окна, popover, удаление диалога, fullscreen/exit, клики вне окна, настройки, скрытие, перетаскивание/resize/reset и сохранение черновика.
- Авторизованные Panel-поиск/бонусы и API-записи МойСклад **не проверены end-to-end** без пользовательской сессии/ключа. Транспорт проверен отдельно, запись бизнес-данных не выполнялась.
- CSRF/419-повтор проверяются настоящим расширением в Chromium с явно синтетическими HTTP fixtures; реальная отправка тестовой cookie отдельно подтверждается `Network.requestWillBeSentExtraInfo`, потому что Playwright routing видит запрос до добавления Cookie. Live-запрос к Panel в неавторизованном профиле безопасно завершается без новой вкладки. Эти проверки не подменяют авторизованную проверку production Panel.
- Исходный GitHub URL дополнительных замен расписания находится в приватном `hatiko`: анонимно возвращает 404. Существующий fallback к встроенным заменам сохранён; токен GitHub в пакет не добавляется.
