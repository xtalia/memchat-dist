# Хатико · Memchat для Chrome

Автономное расширение Chrome **Manifest V3**, версия `8.9.0.4` (`8.9.0-chrome.4`). Расширение использует неизменённое ядро Memchat 8.9.0-alpha.1 и локальные extension-адаптеры. Tampermonkey не нужен.

## Изменения расширения 8.9.0.4

- Фоновый MS-опрос использует тот же `Accept: application/json;charset=utf-8`, что проверенный прямой API-клиент; отдельный regression проверяет эту ветку.

- Убраны локальные очереди, интервалы, лимит параллельности и persisted quota/leases МойСклад — и во вкладке, и в worker.
- При временной ошибке чтения — один повтор конкретного запроса, без блокировки остальных вкладок. Записи не повторяются вслепую.
- Сохранены единый фоновый опрос, приватное хранилище, актуальность ключа и Panel-сессия из 8.9.0.3.

## Изменения расширения 8.9.0.3

- Компактные `bearer / panel` находятся в шапке, на месте прежней строки «Bearer: 200 — валиден». Отдельного ряда ниже шапки и дублирования HTTP-статуса больше нет.
- Настройки, Bearer, кеши и безопасная история перенесены в закрытую `chrome.storage.local` расширения. Миграция запускается при первом открытии каждого поддерживаемого сайта; сохраняет раздельные данные сайтов/аккаунтов. Сайт больше не служит постоянным хранилищем Memchat.
- Старые ключи удаляются только после подтверждённого сохранения и read-back. Чужие ключи и DEV-данные не затрагиваются; конкурентно изменённое значение не удаляется. Конфликтующие старые копии сохраняются только в приватном migration backup и не откатывают актуальные настройки. Ошибка/квота закрывает сохранение с заметным предупреждением, без fallback в хранилище сайта.
- Panel: наличие CSRF само по себе не означает вход. Перед успехом worker подтверждает доступ к защищённому `/api/search/filters`; куки используются из того же профиля Chrome. Ошибки 401/403/419 сбрасывают соответствующий кеш, но не новую сессию из позднего ответа старого запроса. Нажатие `panel` повторяет проверку после входа.
- Формат обновления V2 и семь файлов пакета не изменились; имеющийся V2-обновлятор совместим. Новых разрешений Chrome нет.

## История: расширение 8.9.0.2

- Один опрос заказов в service worker на профиль Chrome; `chrome.alarms` вместо отдельного таймера каждой страницы. Нет ограничения общего числа страниц/заказов. Одновременные ручные проверки делят один запрос. Искусственная межзапросная задержка для фонового опроса снята; реальные квоты/cooldown API и общая параллельность сохранены.
- Настройки оповещателя общие для вкладок с тем же Bearer. Открытие старой вкладки не перезаписывает настройки; конфликт правок требует повторного изменения. Другой Bearer не переключает фоновый аккаунт без явного сохранения.
- «Проверка заказов»: **Получить товары** показывает названия, количества и штрихкоды; **Что добавлено** показывает превышение количества во внутренних заказах относительно заказов покупателей по этому же снимку, без сети. Настройка внутренних заказов необязательна для основного списка. Неполная загрузка не считается успехом.
- Иконка собаки на панели Chrome; отдельные 🟢/🔴/🟡 `bearer` и `panel`. Это результат последней проверки, а не гарантия постоянного доступа. Нажатие повторяет проверку.
- Фоновая конфигурация и Bearer хранятся только в закрытой `chrome.storage.session` до завершения браузерной сессии. После перезапуска Chrome открой Memchat на поддерживаемой странице для повторного подтверждения ключа. Опрос работает без открытой страницы после первоначальной настройки, пока Chrome запущен; звук/уведомления в странице требуют живой подходящей вкладки и разрешения autoplay. ОС может задерживать alarms при сне.

### Важно: переход с установщика V1 на V2

Иконка — новый, седьмой файл расширения. Формат описателя **MEMCHAT_UPDATE_V2**; новые обновляторы принимают V1 и V2, старые V1 безопасно отклоняют новый описатель без изменения установленной папки. **Один раз скачай новый ZIP, замени соседние файлы обновлятора и запусти их** (инструкция ниже). Не удаляй расширение и не меняй путь установки.

Публикация этого пакета на GitHub не является публикацией в Chrome Web Store; Unlisted/автообновления Web Store — отдельный канал.

## История ядра: 8.9.0-alpha.1

Базовое ядро ранее опубликовано как предварительная версия. Перед обновлением сохрани настройки; обновлятор оставляет резервную копию прежних файлов.

- «Сегодня / Завтра»: кеш на 12 часов, выключатель и принудительное обновление.
- Справочники: постоянный кеш, привязанный к Bearer, и ручное обновление с честным статусом неполной загрузки.
- Отдельная вкладка настроек «Правила и замены».
- Создание контрагента больше не заменяет его в документе; ручная замена сохранена, ошибки поиска отменяют check-then-create.
- «Автопродажа» удалена; ручные операции и JSON-автозаполнение сохранены.
- «Новые заказы»: несколько организаций, подпись источника, пагинация и явный частичный результат при сбое.
- Общая очередь запросов МойСклад, ограничение параллельности и обработка cooldown.

Для прежнего timing-теста top-layer фиксированное ожидание заменено ограниченным ожиданием наблюдаемого результата; обычный suite и реальный Chromium проходят. Авторизованные операции с настоящими бизнес-документами в проверках не выполнялись.

## Установка и обновление

**Скачать:** [memchat-chrome.zip](https://github.com/xtalia/memchat-dist/raw/refs/heads/main/memchat-chrome.zip) · [релизы](https://github.com/xtalia/memchat-dist/releases)

### Установить впервые

1. Распакуй ZIP **в постоянное место**, например `D:\Tools\Memchat` или `~/Applications/Memchat`. Не запускай из ZIP и не оставляй рабочую папку во временном каталоге.
2. **Отключи Memchat в Tampermonkey**, включая DEV-версию: одновременный запуск может дублировать обработчики и уведомления.
3. Открой `chrome://extensions`, включи **Режим разработчика** справа сверху.
4. Нажми **Загрузить распакованное расширение**, выбери **внутреннюю папку `chrome-extension` с `manifest.json`**, не ZIP и не родительскую папку с обновлятором.
5. Перезагрузи рабочие вкладки МойСклад, Bitrix24 и Hatiko. Закрепи «Хатико · Memchat» в панели Chrome.

```text
Memchat/
  chrome-extension/          ← эту папку выбираем в Chrome
    manifest.json
    content.js
    worker.js
    ...
  Update-Memchat.cmd          ← двойной клик на Windows
  Update-Memchat.ps1          ← Windows PowerShell 5.1 / PowerShell 7
  Update-Memchat.command      ← двойной клик на macOS
  update-memchat.sh           ← Bash на macOS / Linux
  README.md
```

**Не перемещай и не переименовывай установленную папку:** Chrome использует этот путь. Обновлятор сохраняет его неизменным.

### Обновить на Windows

1. Двойной клик по **`Update-Memchat.cmd`** рядом с установленной `chrome-extension`. Соседний `.ps1` должен оставаться рядом. Администратор, Python и Node.js не нужны.
2. Дождись сообщения об обновлении либо о том, что актуальная версия уже установлена. Если Windows просит подтвердить запуск скачанного файла, сначала проверь, что он получен из `xtalia/memchat-dist`.
3. На `chrome://extensions` нажми **круглую стрелку «Перезагрузить» на карточке «Хатико · Memchat»**, не общую кнопку «Обновить» вверху страницы.
4. Перезагрузи рабочие вкладки.

Можно запустить и из PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Update-Memchat.ps1"
```

`Bypass` действует только для этого процесса; глобальная политика выполнения не меняется.

### Обновить на macOS

1. Двойной клик по **`Update-Memchat.command`** рядом с `update-memchat.sh` и установленной `chrome-extension`.
2. Дождись результата в Terminal.
3. Нажми **круглую стрелку на карточке Memchat** в `chrome://extensions`, затем перезагрузи рабочие вкладки.

Если `.command` не открывается, запусти из Terminal, подставив свой путь:

```sh
bash "$HOME/Applications/Memchat/update-memchat.sh"
```

Если архиватор потерял executable bit у доверенного `.command`, достаточно `chmod +x "/путь/к/Update-Memchat.command"`. Отключать Gatekeeper не нужно. Используются штатные `curl`, `unzip`, `shasum`; Python / jq / Node.js не нужны.

### Linux / запуск из терминала

```sh
bash "/путь/к/Memchat/update-memchat.sh"
```

Нужны Bash, `curl`, `unzip` и `shasum` либо `sha256sum`.

### Если расширение уже установлено из старого ZIP

Один раз скачай новый ZIP и перенеси **файлы обновлятора** в родительскую папку своей **существующей** `chrome-extension`:

- Windows: `Update-Memchat.cmd` и `Update-Memchat.ps1`.
- macOS: `Update-Memchat.command` и `update-memchat.sh`.

После этого запускай соответствующий файл. Новую `chrome-extension` вручную копировать не нужно. **Удалять расширение из Chrome и устанавливать заново не надо**: сохраняем путь и настройки.

Если установленная папка называется иначе или находится не рядом, укажи путь именно к папке с `manifest.json` и `build-info.json`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Update-Memchat.ps1" -TargetDirectory "D:\Tools\MyMemchat"
```

```sh
bash "/путь/к/update-memchat.sh" --target "/путь/к/установленной/папке"
```

### Что делает обновлятор

- Получает [описатель опубликованной версии](https://raw.githubusercontent.com/xtalia/memchat-dist/main/memchat-update.txt) и ZIP из **нашего GitHub Releases**, включая текущий канал расширения. Описание — данные, не исполняемый скрипт.
- Проверяет SHA-256 архива и каждого файла расширения; до проверки рабочую папку не трогает.
- Подготавливает соседнюю папку и заменяет установленную **по прежнему пути**. Предыдущая папка целиком остаётся в резервной копии рядом; её путь выводится в конце. Ненужные старые копии можно удалить вручную.
- При ошибке скачивания/проверки оставляет прежнюю версию; при неудаче замены пытается вернуть её из резервной копии. Отказывается работать с посторонней папкой, небезопасным ZIP, понижением версии и параллельным обновлением той же папки.
- Если версия и все файлы уже совпадают, ничего не заменяет; повреждённые файлы той же версии восстанавливает из проверенного пакета.
- Не трогает профиль Chrome, cookie, историю/настройки, не запускает скачанные программы и не обновляет сам выполняющийся скрипт.

**Это обновление по твоему запуску, не фоновая автоустановка.** Chrome не перечитывает unpacked-файлы сам: круглая стрелка на карточке расширения и перезагрузка вкладок остаются ручными шагами. Публикации в Chrome Web Store в этом релизе нет.

Для отката восстанови папку из напечатанной резервной копии **по прежнему пути**, затем перезагрузи расширение/вкладки. Занятую блокировку не удаляй, пока другой процесс обновления работает.

**После миграции 8.9.0.3 не удаляй расширение из Chrome:** удаление стирает его `chrome.storage.local`. Обновление/перезагрузка по прежнему пути сохраняют данные. Резервная копия папки обновлятора содержит код, не данные профиля. При ручном откате до 8.9.0.2 старая версия не увидит новое приватное хранилище; обратной миграции секретов на сайты нет. Возвращение к 8.9.0.3 с прежним ID снова использует сохранённые данные.

## Управление расширением

- **ЛКМ по значку** создаёт/показывает основной чат; повторный клик скрывает его, сохраняя черновик, вкладку и историю. Плавающие окна при этом не закрываются.
- **ПКМ по значку → Сбросить положение окон** возвращает окна в исходное положение, удаляет сохранённую позицию. История и настройки не очищаются.
- Popup-меню и пункта отладки нет. На неподдерживаемой странице или при необходимости перезагрузки значок показывает `!`; подсказка объясняет причину.

Chrome 120+. Пользовательский профиль при разработке/проверках не меняется.

## Авторизация и данные

- Для Panel войти в `https://panel.hatiko.ru/` в **том же профиле Chrome**. Расширение использует существующую сессию браузера; пароли не входят в пакет.
- CSRF получается фоновым HTML-запросом `/search`, затем вход подтверждается read-only JSON-запросом `/api/search/filters`. Вкладку Panel держать открытой и копировать токен вручную не нужно. Одновременные обращения делят один flight и кеш в памяти worker до 12 минут; после его остановки токен запрашивается заново. Ошибка 401/403/419 запускает принудительное обновление и не более одного повтора API-запроса.
- CSRF не записывается в постоянное хранилище. Старый `memchat:panelCsrf_v1` удаляется для посещённого сайта. При истёкшем входе расширение сообщает об ошибке, но само не открывает окна/вкладки. Войди в Panel в том же профиле и нажми индикатор `panel`. Пароли, CAPTCHA и 2FA не обходятся; политика cookies/браузера может помешать передаче сессии.
- Bearer API МойСклад включается в существующих настройках Мемчата. Ключ не вшит в расширение.
- Исходные production-ключи читаются из `localStorage` только для миграции. В дальнейшем неизменённое ядро получает синхронный локальный адаптер, а worker сохраняет значения в `chrome.storage.local` с `TRUSTED_CONTEXTS`. Прямой доступ content contexts к local storage расширения закрыт; сообщения проверяют extension id, top frame и разрешённый origin. DEV-состояние не переносится.
- Настройки/история по-прежнему раздельны для разных сайтов/профилей. Исключения — единый оповещатель заказов и кеш CSRF Panel на профиль расширения. Bearer перенесён вместе с настройками. Межвкладочные изменения идут приватным runtime-каналом без DOM StorageEvents; старый Bearer блокируется, в том числе по актуальному сохранённому значению перед отправкой MS-запроса. Это не шифрование диска: поля ввода/результаты UI остаются DOM страницы, а пользователь с доступом к профилю может читать данные расширения.
- Телефоны вкладки «Бонусы» по-прежнему исключены из сохраняемой истории.
- Пакет не содержит паролей, Bearer-ключей, пользовательских данных или телеметрии. Все исполняемые скрипты локальны; сетевые ответы — данные/HTML/JSON, не remote code.

## Разрешения

- Site access: `online.moysklad.ru`, `*.bitrix24.ru`, `*.hatiko.ru` — только исходные `@match` сайта для content script и управления текущей рабочей вкладкой.
- Network access: исходные `@connect` (`hatiko.ru` и поддомены, Panel, `docs.google.com`, GitHub/raw, `api.moysklad.ru`).
- `alarms` — один периодический фоновый опрос заказов, не отдельный таймер страницы.
- `activeTab` — действие по текущей рабочей вкладке; broad `tabs` не запрашивается.
- `contextMenus` — единственный собственный пункт «Сбросить положение окон» в ПКМ-меню значка расширения, не в меню страницы.
- `storage` — постоянные origin-scoped настройки/история/Bearer в приватной `chrome.storage.local`, и рабочее состояние оповещателя в `chrome.storage.session`. Session-конфигурация живёт до закрытия Chrome; после перезапуска открой Memchat для проверки сохранённого ключа. Cookies и CSRF не копируются в storage; `sync` не используется.
- `declarativeNetRequestWithHostAccess` — выставление фиксированных Origin/Referer для **собственных** запросов расширения к Panel; отдельное правило блокирует внешние redirect destinations. Обычные запросы страниц не переписываются.
- Нет `<all_urls>`, `cookies`, `webRequest`, `scripting`, clipboard permission или externally_connectable.

## Архитектура

- `content.js`: isolated-world async IIFE, миграция/гидратация закрытого Storage-адаптера, GM bridge, неизменённый production userscript и локальные runtime/UI-адаптеры. Toolbar ждёт готовности гидратации. Нет page postMessage bridge. Модули storage встраиваются в существующие content/worker, состав установщика не расширяется.
- `worker.js`: проверенный по sender/domain/method GM transport и отдельная команда фонового CSRF с фиксированным адресом. Cookie-сессии передаются через `credentials: include`; `anonymous` использует `omit`. Bearer разрешён только для `api.moysklad.ru`. CSRF кешируется только в памяти и не выводится в логи.
- `config.js`: allowlists из metadata userscript.
- `controls.js`: Chrome action/context-menu обработчики; управление через private runtime channel без popup, eval и page postMessage bridge. GM-menu регистрации userscript не экспортируются.
- `build-info.json`: версия и SHA-256 точного production input.

Сетевой таймаут отдельной попытки ограничен 30 секундами; пауза перед повтором в него не входит. Табличные/фоновые функции core продолжают жить в открытой вкладке, а не в постоянно работающем worker. Исключение — оповещатель заказов, перенесённый в alarms/worker. Закрытие/заморозка рабочей вкладки останавливает остальные core-функции, как и у userscript; это не сервер мониторинга.

### Запросы МойСклад: без локальных ограничителей

С Chrome 8.9.0.4 нужный запрос отправляется сразу: нет искусственного интервала, общей очереди, лимита параллельности, расчёта веса/остатка квоты или сохранённых reservations/cooldown. Ограничитель standalone userscript отключён только в extension-адаптере. Позиции всех выбранных документов также запрашиваются без локального пула на два документа. Единый фоновый опрос заказов на профиль сохранён — вкладки не дублируют его.

При временной ошибке MS GET/HEAD выполняется **один повтор**: сеть/таймаут, HTTP 408/429/5xx или API 1073. Пауза перед повтором — 500 мс, либо больший `X-Lognex-Retry-After` (миллисекунды) / `Retry-After` (секунды или HTTP-date), если его вернул сервер. Ждёт только конкретный неудачный запрос, другие вкладки продолжают отправку. Успешные rate-limit headers ничего не резервируют. Последняя ошибка возвращается в UI, бесконечного цикла нет.

Обычные 400/401/403/404/422 не исправляются повтором. POST/PUT/PATCH/DELETE автоматически не переигрываются: после потери ответа запись могла уже выполниться. Смена/выключение Bearer и явная отмена прекращают активную работу и отложенный повтор; актуальность ключа проверяется перед каждой попыткой. Неполные позиции и результаты старого аккаунта не становятся успешным снимком.

Старый `memchatMsQuota_v1` больше не читается и не обновляется. Его значения и недоступность session storage сами по себе не блокируют HTTP-транспорт; приватное хранилище настроек и проверка актуального ключа сохранены. Остановка MV3 worker не даёт гарантии завершения его текущего запроса, но после пробуждения новые запросы не ждут старые leases и не воспроизводят их. Серверные ограничения МойСклад остаются на стороне сервиса: отсутствие любых 429 не обещается.

Проверка: `node extension/ms-direct-smoke.cjs` — отдельный headless-профиль, два настоящих content/runtime канала, шесть одновременно активных fixture-запросов, временные ошибки/повтор, смена ключа и настоящий CDP stop/wake. Все HTTP-фикстуры синтетические, реальных записей и токенов нет. `ms-api-audit.md` сохранён как историческое описание удалённого ограничителя, не текущий контракт.

## Сборка и проверки

Исходники расширения: `hatiko/js/memchat/extension/`. Generated userscript вручную не редактировать.

Из `E:/gitreps/hatiko/js/memchat`:

```sh
# После обычной production-сборки memchat.user.js:
python extension/build.py
node --test tests/chrome-extension-*.test.js
node extension/smoke.cjs
node extension/ms-direct-smoke.cjs
node extension/orders-service-smoke.cjs
node extension/storage-smoke.cjs
node extension/updater-smoke.cjs
npm test
python -m unittest discover -s tests/updater -p 'test_*_updater.py'
```

`build.py` не пересобирает и не меняет userscript: получает уже собранный production input, без незавершённых src-правок. Выход: `extension/dist/chrome-extension/`, ZIP с обновляторами/README и внешний `memchat-update.txt`. ZIP детерминированный; `.sh`/`.command` внутри имеют LF и executable bit. Зависимости для Python-сборки не нужны. Четвёртый компонент Chrome version — revision оболочки. Описание обновления публикуется **после** появления неизменяемого ZIP в GitHub Release.

Тесты/офлайн-обновление поддерживают пару локальных файлов, по-прежнему с проверкой издателя, версии, структуры и SHA-256:

```powershell
.\Update-Memchat.ps1 -OfflineIndex ".\memchat-update.txt" -OfflineArchive ".\memchat-chrome.zip"
```

```sh
bash ./update-memchat.sh --offline-index ./memchat-update.txt --offline-archive ./memchat-chrome.zip
```

Не используй непроверенное описание от постороннего источника: хеш защищает от повреждения пакета, но не является цифровой подписью издателя. Обновляторы находятся вне папки расширения и не требуют новых разрешений Chrome.

Smoke использует уже установленный Playwright и отдельный временный headless Chromium профиль. Пути можно задать переменными `MEMCHAT_PLAYWRIGHT` и `MEMCHAT_CHROMIUM`. Windows-проверка обновления: `node extension/updater-smoke.cjs`; ей дополнительно нужен checkout `memchat-dist` с тегом `chrome-v8.9.0.2` (путь `MEMCHAT_DIST_REPO`, по умолчанию `E:/gitreps/memchat-dist-orders`). На Windows для обоих smoke задай `TEMP` и `TMP` в рабочий scratch-каталог. Он проверяет действительную загрузку пакета, native-menu регистрацию, переключение видимости, сброс позиций, сохранение текста/истории/настроек, калькулятор, runtime HTTP channel, публичный GitHub redirect и live `hatiko.ru`. В headless нет видимого toolbar: вызываются те же функции, которые зарегистрированы в Chrome action/context-menu событиях, с настоящими tabs/runtime APIs и content scripts. Пользовательский профиль и бизнес-документы не меняются.

## Окна поверх страницы

Основное окно, плавающие настройки и диалоги Мемчата используют **top layer браузера** через немодальный `popover="manual"`: обычный `z-index` сайта их не перекрывает. Внешние клики проходят к странице, если не попали в окно; черновик, история, размеры и кнопка скрытия сохраняются. При открытии новых popover/dialog страницы слой поднимается заново; внутри модального диалога host размещается в его поддереве, чтобы окно не стало `inert`.

Это верхний слой **текущей вкладки**, не режим «поверх всех приложений» Windows и не размещение над интерфейсом самого Chrome. На браузере без Popover API остаётся исходное поведение; Chrome 120+ поддерживает используемый API.

## Границы проверки

- Нативный запуск macOS на Windows-машине не проверяется. Проверка Bash-ветки, состава пакета и executable flags не подменяет проверку на самом Mac.
- Input взят из отдельного release-worktree без постороннего WIP; точные входные байты и SHA-256 зафиксированы в `build-info.json`. В этом extension-only релизе оба существующих userscript не изменяются.
- Проверки расширения: полный обычный JavaScript suite — **231 passed, 0 failed**. Packaged smoke в Chromium 151 проверяет native/runtime controls, верхний слой окон, modal/fullscreen, настройки, сохранение черновика и транспорт. Тест внешнего top-layer toggle теперь ограниченно ждёт наблюдаемого результата, а не фиксированные 20 мс между двумя вложенными таймерами. Runtime top-layer не изменялся.
- Windows upgrade-smoke проверил переход `8.9.0.2` → `8.9.0.4` в отдельном Chromium с сохранением ID, режима калькулятора и истории и миграцией из website-localStorage в Chrome storage. Отдельный storage smoke проверяет очистку сайта, рестарт браузера, изоляцию origins и смену ключа в двух вкладках. Пользовательский профиль не меняется.
- Авторизованные Panel-поиск/бонусы и API-записи МойСклад **не проверены end-to-end** без пользовательской сессии/ключа. Транспорт проверен отдельно, запись бизнес-данных не выполнялась.
- CSRF/419-повтор проверяются настоящим расширением в Chromium с явно синтетическими HTTP fixtures; реальная отправка тестовой cookie отдельно подтверждается `Network.requestWillBeSentExtraInfo`, потому что Playwright routing видит запрос до добавления Cookie. Live-запрос к Panel в неавторизованном профиле безопасно завершается без новой вкладки. Эти проверки не подменяют авторизованную проверку production Panel.
- Исходный GitHub URL дополнительных замен расписания находится в приватном `hatiko`: анонимно возвращает 404. Существующий fallback к встроенным заменам сохранён; токен GitHub в пакет не добавляется.
